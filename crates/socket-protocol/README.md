# Legacy text protocol codec

Bounded Engine.IO 3/4 text polling and legacy Socket.IO text packets. Socket.IO protocol 4 here means the wire revision used by Socket.IO 2.x, not the Socket.IO 4.x library version.

Supports all seven Engine.IO text packet markers and polling batches with JavaScript UTF-16 length prefixes. Socket.IO supports namespace connect/disconnect and JSON events. It rejects acknowledgement IDs, binary attachments, error packets and connect payloads. Payload bytes, packet bytes and batch counts have independent limits. JSON deserialization uses Serde's recursion limit; encoding rejects excessive caller-built nesting and uses a bounded writer.

The realtime services also use the explicit Engine.IO 4 record-separated payload functions and `decode_socket_lenient`, which accepts an object payload on namespace CONNECT while still authenticating characters through their service auth event. Binary transport and WebSocket upgrades remain unsupported; strict decoding behavior stays available to the compatibility experiment.

`tests/fixtures/engine-v3.json` was generated by engine.io-parser 2.2.1 through the pinned Socket.IO 2.5.0 development client. The generator remains on the development branch at `tests/compatibility/socket-client/generate-fixtures.cjs` and is excluded from runtime review. It covers ping, namespace connect, Unicode, JSON event data and close. These are generated packets, not Flash captures. Actual-client realtime acceptance remains open.

Protocol references: [Engine.IO revision 3](https://github.com/socketio/engine.io-protocol/tree/v3), [Socket.IO revision 4](https://github.com/socketio/socket.io-protocol/tree/v4).
